# IT and cybersecurity claim checks

Use these checks when a claim's technical meaning affects credibility. They are diagnostic prompts, not a required checklist for every resume.

| Claim | Check before strengthening it |
|---|---|
| Reduced vulnerability risk by X% | Was X a count, density, severity, overdue backlog, exposure duration, or modeled risk? Name the metric actually measured. Account for scope changes and accepted exceptions. |
| Improved patch compliance / coverage | Define eligible population, reporting period, baseline, and exclusions. Agent installation is not proof of healthy reporting or policy enforcement. |
| Improved MTTR / MTTD | Define detect, acknowledge, contain, restore, or remediate; unit, cohort, and mean/median. Do not invent comparability across incident classes. |
| Reduced false positives | Distinguish alert-volume reduction from false-positive rate. Were detections validated so suppressing true positives did not produce the apparent improvement? |
| ATT&CK coverage | Mapping rules to techniques differs from tested detection of scenarios. State what was validated and in what environment. |
| Prevented breaches / saved $X | Distinguish measured savings, avoided planned spend, modeled loss reduction, and an unprovable counterfactual. Do not turn “no observed incidents” into causation. |
| Led red team / pentesting | Preserve authorized scope, personal role, engagement type, and retest/remediation outcomes. A lab exploit does not become a client engagement. |
| Implemented zero trust | Name actual identity, access, segmentation, device, or telemetry controls and scope; do not imply a strategy was fully completed. |
| SOC 2 certified | Clarify attestation/reporting and the candidate's contribution. Do not call every audit framework a certification. |
| ISO certified / HIPAA compliant / FedRAMP authorized | Identify organization/system scope, actual outcome, and candidate role. A control mapping is not certification or authorization. Verify current program terminology when needed. |
| OAuth authentication | OAuth concerns delegated authorization; if authentication is meant, verify the use of OIDC or another mechanism. Do not silently invent an implementation. |
| EPSS / CVSS / KEV prioritization | Treat EPSS as an exploitation-likelihood signal, CVSS as severity, and KEV as a known-exploitation catalog. Do not equate any single input or arbitrary product with measured business risk. |
| Recovery / high availability | Restore testing, RTO, RPO, uptime, and failover are different measures. Backups existing does not prove successful recovery. |
| Cloud / AI security | Distinguish configuration work, architecture, evaluations, guardrails, and production responsibility. A demo or course is not deployed control effectiveness. |

For an unclear claim, preserve established wording or ask a precise question; do not replace it with an unsupported technical narrative. Source factual explanations from current primary references if uncertain. Use sanitized detail that demonstrates judgment without exposing credentials, sensitive targets, client identities, patient information, or restricted methods.
