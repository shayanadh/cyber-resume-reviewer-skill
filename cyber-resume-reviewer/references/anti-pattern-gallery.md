# Editing patterns with bounded corrections

Use a relevant pattern to explain an edit, not as a label for the candidate. The source text below is illustrative. Replacements use only its facts; stronger claims require additional evidence. Do not mechanically apply every row.

| Pattern | Illustrative source | Supported action |
|---|---|---|
| Generic adjectives | “Passionate, dynamic security professional.” | Remove the adjectives; build a summary from actual role evidence elsewhere, not invented years or specialties. |
| Vague objective | “Seeking a challenging security role.” | Replace with the stated target and established transferable evidence; a concise transition objective may be useful. |
| Broad expert claim | “Expert in cloud, audit, red team, identity, OT.” | Ask which domains have recent depth; prioritize established strengths without declaring the breadth impossible. |
| Ungrouped skills | “Linux, Splunk, Python, AWS, PowerShell.” | Group only these: Systems: Linux; Detection: Splunk; Cloud: AWS; Scripting: Python, PowerShell. |
| Graphical self-rating | “Python 80%.” | Remove the arbitrary rating; retain Python if candidate-stated and ask for a use example when central. |
| Duty without detail | “Responsible for vulnerability management.” | Keep the scope modest: “Supported vulnerability management” only if support matches the role; otherwise ask what ownership entailed before changing the verb. |
| Tool-only bullet | “Used Splunk.” | Ask what the candidate did in Splunk; do not manufacture detections or reduced false positives. |
| Vague contribution | “Helped with incident response.” | “Supported incident response.” Ask for personal actions before using “contained” or “led.” |
| Strategy shorthand | “Implemented zero trust.” | Ask which controls, systems, and responsibilities; do not substitute a made-up MFA or segmentation project. |
| Output count presented as impact | “Created 12 dashboards.” | Retain 12 dashboards as output; ask who used them and what changed, without asserting risk reduction. |
| Inflated but unspecific | “Spearheaded a transformative initiative.” | Replace with the initiative and actual contribution once supplied; adjective deletion alone cannot recover missing facts. |
| Title-based credibility assumption | Analyst claims enterprise design contribution | Examine actual ownership and evidence; a junior title does not preclude meaningful design work. |
| Incomplete chronology | “Systems Engineer, through 2023.” | Ask for start date; do not invent months or attribute deception. |
| Overlong credential list | Many candidate-stated credentials | Prioritize target-relevant credentials; do not call legitimate credentials fake or automatically lower-value. |
| Unknown credential status | “CISSP.” | Preserve the stated credential, ask about status if material; no expiry date is not proof of expiration. |
| Course called certification | “Certification: introductory cloud course.” | Use Training or Coursework unless an actual certification was awarded. |
| Contact in header only | Observed DOCX header placement | Move contact into main body where useful and test extraction; do not claim universal rejection. |
| Interleaved columns | Extracted dates mixed with unrelated bullets | Simplify the application copy and verify reading order; diagnose the observed failure. |
| Scanned source | PDF has image pages and no extracted text | Re-export from source or OCR and verify; original layout may still be visually readable. |
| Leadership scope obscured | “Managed SOC team of 12.” | Preserve this useful scope. Ask about decisions or outcomes for an additional bullet; do not replace it with an invented operating-model transformation. |
| Board access inflation | “Prepared slides for CISO board briefing.” | “Prepared board-briefing materials for the CISO.” Do not claim the candidate briefed the board. |
| Career level mismatch | Manager intentionally targeting an IC role | Explain the stated direction and surface current hands-on evidence; do not infer disloyalty or conceal titles. |
| Acronym ambiguity | “SOC experience.” | Clarify security operations or SOC reporting; do not select one by guess. |
| Disclosure/clearance ambiguity | “Public Trust clearance.” | Ask for confirmed suitability/clearance wording; do not upgrade to Secret or infer eligibility. |
| Unmeasured prevention | “Prevented all breaches.” | Ask what was measured. Use the actual control or observed result rather than an absolute prevention claim. |
| Lab presented as employment | Personal detection lab under Experience with employer-like title | Move to Projects or clearly label personal/lab work; keep the actual technical achievement. |
| Excessive emphasis | Many visible bold fragments distract from role and results | Simplify emphasis based on rendered hierarchy; no arbitrary numerical quota. |
| Overtranslation | “Patched servers” becomes “led exposure reduction with EPSS” | Retain patching contribution; ask about prioritization before adding tools, leadership, or outcomes. |
| Fabricated qualitative impact | “Wrote documentation” becomes “reduced onboarding time” | “Wrote technical documentation” only if technical context is established; ask about use before asserting improvement. |
| Conflated populations | “Closed 400 findings” becomes “patched 400 systems” | Keep findings and systems distinct; ask whether closure involved patching, retirement, suppression, or exceptions. |
| Unstated regulatory scope | Employer is a hospital, rewrite says “owned HIPAA compliance” | Preserve employer/industry context; add regulatory responsibility only if candidate-stated. |
| Artificial keyword match | “No Terraform experience” is counted as Terraform qualification | Treat it as a negated mention; never upgrade lexical presence to capability. |

Useful corrections sometimes leave a modest bullet modest. Put questions for missing substance beside the edit instead of embedding a fictional achievement with a small “verify” note.
