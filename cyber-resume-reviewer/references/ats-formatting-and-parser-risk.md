# Original-file parsing and readable layout

Separate **upload acceptance**, **text extraction**, **field mapping**, **search/ranking**, and **employer screening questions**. They are different operations. A local extraction check tests only part of the path. Do not promise an “ATS pass.”

## Evidence ladder

| Evidence available | What can be said |
|---|---|
| Pasted text | Content order and headings in the supplied text; original layout and parser behavior unassessed |
| Rendered pages only | Visible readability; extraction unassessed |
| Original file plus extraction | Whether local extraction retained text and order; target ATS behavior still unverified |
| Actual application preview/fields | Whether that system populated those fields correctly for that submission |

If a tool cannot extract the file, inspect rendered pages/OCR or request a readable copy. Do not claim the file is corrupt solely because a particular tool failed.

## Conservative application copy

Prefer a straightforward column, standard headings, readable type, consistent employer/title/date grouping, and text contact information in the main body. Keep essential information out of graphics alone. Use the employer's requested format; otherwise choose an accepted text-based PDF or DOCX appropriate to the workflow.

Tables, text boxes, columns, headers, and unusual spacing can cause partial extraction or field mapping errors. Flag observed effects and simplify when useful; do not say their mere presence causes automatic rejection. Inspect how each role title remains associated with employer, dates, and bullets. Do not infer layout from whitespace alone in extracted text.

Text labels next to contact icons are optional when the address/number/link is already clear text. Color and bold are design choices: preserve contrast, meaningful grouping, and grayscale readability. Do not impose arbitrary bold-word counts or imply restrained color is a parser defect. Replace graphical proficiency ratings with descriptions of actual work.

## Verification for generated files

Open/render all pages; check clipping, orphaned headings, page breaks, hyperlinks, and selectable text. Extract text and compare key names, titles, dates, skills, and role-to-bullet associations. Confirm actual page count, not a character-based estimate. In DOCX, check tables/text boxes/header content if relevant. Plain-text output cannot verify final font, margins, line count, or pages.

Do not upload a private resume to a third-party scoring site for validation without the user's authorization.

## Source boundary

Greenhouse documents that formatting can cause partial parsing and that a failed parse can leave the resume attached for manual field entry. This supports cautious layout advice, not a universal rejection rule. See [Greenhouse parsing guidance](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse), checked 2026-09-07. Recheck current vendor documentation for platform-specific file limits or behavior; upload limits and parsing limits may differ.
