# Truthful bullet rewrites

A useful bullet communicates a specific contribution. Choose a structure suited to the source: action + object, action + scope, action + result, or judgment + constraint + decision. Use tool names and metrics when they add useful evidence. Do not require every bullet to contain scope, tool, and measurable outcome.

## Two outputs for thin evidence

1. **Supported edit:** Improve wording using only established facts. It may remain modest.
2. **Optional evidence question:** Ask what would permit a more substantive bullet. Do not place the hoped-for achievement in the supported edit.

| Source | Supported rewrite | Question for a stronger version |
|---|---|---|
| Helped with incident response. | Supported incident response. | What did you personally do: collect evidence, investigate, communicate, contain, or recover? |
| Created dashboards and reports for leadership. | Created leadership dashboards and reports. | What measures, audience, and decisions were involved? |
| Managed Active Directory for 5,000 users. | Administered Active Directory for 5,000 users. | Did your work include account lifecycle, GPOs, or access reviews? Which ones? |
| Wrote Python automation. | Developed Python automation. | What task did it automate and how was the result measured or validated? |
| Monitored SIEM alerts and escalated incidents. | Monitored SIEM alerts and escalated incidents. | Which investigations or escalation criteria best demonstrate your judgment? |

Leaving a sound bullet unchanged is a valid recommendation. “Supported,” “assisted,” and “maintained” can accurately describe important work. A stronger verb is not permission to increase ownership.

## With richer source evidence

Illustrative source: “I replaced manual access exports with a Python script. Access-review preparation went from 4 hours to 45 minutes per monthly cycle. The team approved and ran the reviews.”

Supported bullet: “Automated access-review data exports with Python, reducing monthly preparation from 4 hours to 45 minutes.”

Do not add “owned access governance,” “eliminated identity risk,” or annual savings unless established. If useful, 81.25% less preparation time can be derived from the stated baseline; explain the calculation outside the resume and prefer the clearer before/after wording. Verify units, denominator, period, and attribution before any derived metric.

## Evidence without a percentage

Valid evidence includes a deployed control, adopted runbook, reproduced defect, restored service, retest result, approved decision, resolved audit finding, or supported operational scope. A lab bullet can state what was built and tested without implying production use. Do not invent “improved efficiency” or “reduced risk” just because a task sounds beneficial.

## Placeholder handling

Default to a clean supported rewrite. If the user wants a fill-in draft, use only `[VERIFY: precise missing fact]`. Identify every occurrence by location and the fact needed. Distinguish essential missing fields from optional stronger evidence. Do not demand metrics when no defensible metric exists. Never leave conditional achievements in an otherwise submission-ready resume.

## Editing details

Keep actual employers, titles, and dates. Use present tense for continuing duties and past tense for completed achievements, including completed work in the current role. Vary phrasing naturally; preserve technical nouns. Avoid repeated “leveraged,” inflated causal verbs, arbitrary bullet-length rules, and numbers that obscure the contribution. Reorder strongest evidence within roles while keeping chronology clear.
